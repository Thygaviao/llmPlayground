# 🎓 LLM Assessor Playground & Evaluation Platform

Открытая интерактивная платформа для онбординга, обучения и сертификации асессоров, разметчиков данных и AI/ML-специалистов (LLM / RLHF / SFT / DPO / CV / NLP), а также рабочая среда для формирования обучающих датасетов.

---

## 🌟 Основные модули системы

### 1. 🎓 Обучающий тренажёр LLM (12 боевых кейсов)
* Пошаговое обучение оценке ответов языковых моделей по четырём ключевым критериям:
  * **Следование инструкции (Instruction Following)**
  * **Фактическая точность (Factuality)**
  * **Полнота ответа (Completeness)**
  * **Связность и грамотность (Coherence & Literacy)**
* Детекция ловушек: «эффект ореола», галлюцинации, скрытые деструктивные команды (`git reset --hard`), утечки контекста (Jailbreak / Cinema prompt bypass), псевдоматематика.
* Попарное сравнение моделей (Side-by-Side / DPO) с раздельными оценками модели A и модели B.
* Автоматический расчет **согласованности с экспертным эталоном (Agreement Score)** с детальной декомпозицией вклада каждого компонента.

### 2. 👁 Разметка Computer Vision (Object Detection / BBox)
* Обучение разметке дефектов на производстве (дефектоскопия металла), аэрофотосъемке и беспилотном транспорте.
* Расчет метрики **IoU (Intersection-over-Union)** с порогом строгости.
* **Строгая валидация классов объектов**: предотвращение ошибок классификации (например, выделение трещины вместо скола или пятна), защита от False Positive в детекторах YOLO/Faster-RCNN.

### 3. 📝 Разметка NLP (NER, Sentiment, Search Relevance)
* Извлечение именованных сущностей (NER) с точностью по токенам.
* Тональность текста с учетом сарказма и контекста.
* Оценка релевантности поисковой выдачи по трехуровневой шкале.

### 4. 🧪 Экспорт данных и персистентность
* **JSONL (DPO/SFT):** формат `chosen`/`rejected` и `messages` для TRL, Axolotl, Hugging Face.
* **CSV / Excel:** детальные таблицы результатов разметки.
* Полная сохранность всех разметок и состояния в локальном хранилище браузера (LocalStorage).

## 🌐 Развертывание на GitHub Pages (через GitHub Actions)

Платформа поддерживает полностью автономный статический режим и автоматический деплой на **GitHub Pages** с использованием воркеров GitHub Actions.

### Как включить GitHub Pages:
1. Запушьте код в ваш GitHub-репозиторий:
   ```bash
   git push origin main
   ```
2. В интерфейсе GitHub откройте:
   **Settings** ➔ **Pages** ➔ в блоке **Build and deployment** выберите **Source: GitHub Actions**.
3. Пайплайн `.github/workflows/deploy-pages.yml` запустится на воркере `ubuntu-latest`:
   * Выполнит проверку синтаксиса Python и тесты REST API.
   * Выполнит валидацию классов CV, согласованности DPO и сквозные E2E тесты.
   * Соберет и опубликует статический сайт на `https://<ваш_логин>.github.io/<репозиторий>/`.

### Особенности автономного режима на GitHub Pages:
* **Полная функциональность:** все 12 обучающих кейсов LLM, 3 CV-кейса с детекцией объектов и 3 NLP-кейса работают прямо в браузере.
* **Персистентность в LocalStorage:** разметка обучающих кейсов, прямоугольные рамки дефектов и выделенные сущности NER сохраняются при обновлении страницы.
* **Автономный экспорт:** формирование отчётов в CSV и датасетов для обучения моделей в JSONL происходит локально через браузерные `Blob`.

## 🐳 Развертывание через Docker

Для запуска собственного сервера с SQLite-бэкендом:

### 1. Запуск контейнера
```bash
docker compose up -d --build
```

Сервер станет доступен по адресу:  
👉 **http://localhost:8000**

### 2. Управление контейнером
```bash
# Просмотр логов
docker compose logs -f trainer

# Проверка статуса (включая встроенный healthcheck)
docker compose ps

# Остановка
docker compose down
```

> **Важно:** Файл базы данных `./train.db` монтируется через Docker Volume (`./train.db:/app/train.db`), благодаря чему все сохраненные разметки и статистика оценок надежно сохраняются при перезапусках.

---

## 💻 Локальный запуск без Docker

Приложение написано исключительно на **стандартной библиотеке Python 3** и не требует установки сторонних зависимостей через `pip`:

```bash
# Инициализация базы данных (при первом запуске)
python3 init_db.py

# Запуск сервера
python3 server.py
```

Откройте в браузере: **http://localhost:8000**

---

## 🧪 Запуск автоматических тестов

Запустить полный набор тестов локально:
```bash
# 1. Тесты валидации классов Computer Vision
node tests/test_cv_class_validation.js

# 2. Тесты согласованности шкал DPO (Таблица / Окно просмотра / JSONL экспорт)
node tests/test_dpo_scores_consistency.js

# 3. Сквозные тесты всех 12 LLM, 3 CV, 3 NLP кейсов
node tests/test_e2e_cases_and_state.js

# 4. Тесты бэкенда Python REST API
python3 tests/test_server_endpoints.py
```

## 📁 Структура проекта

```text
├── .github/workflows/          # GitHub Actions CI/CD пайплайны
│   └── deploy-pages.yml        # Автоматический деплой на GitHub Pages (ubuntu-latest воркер)
├── Dockerfile                  # Конфигурация Docker-образа (Python 3.11-slim, non-root)
├── docker-compose.yml          # Запуск сервиса с монтированием хранилища SQLite
├── .dockerignore               # Исключения для чистой сборки Docker
├── .gitignore                  # Исключения для Git
├── server.py                   # REST API бэкенд на стандартной библиотеке Python 3
├── init_db.py                  # Скрипт инициализации схемы и эталонов SQLite
├── index.html                  # Единый веб-интерфейс
├── train.db                    # База данных SQLite (кейсы, разметки, пользователи)
├── data/                       # Эталонные датасеты
│   ├── cases.json              # 12 обучающих кейсов LLM
│   ├── cv_cases.json           # 3 обучающих кейса Computer Vision
│   └── nlp_cases.json          # 3 обучающих кейса NLP
└── tests/                      # Автоматические тесты
    ├── test_cv_class_validation.js
    ├── test_dpo_scores_consistency.js
    ├── test_e2e_cases_and_state.js
    └── test_server_endpoints.py
```

## 🔒 Безопасность
* Контейнер Docker работает от выделенного непривилегированного пользователя `appuser` (UID: 1001).
* Встроенный Healthcheck контролирует доступность HTTP-эндпоинта `/`.
* Никаких встроенных секретов и внешних учетных данных в репозитории.
* Все ответы моделей экранируются при отображении для предотвращения XSS-уязвимостей.
